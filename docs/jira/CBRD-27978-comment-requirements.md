## 보고자 제안: PoC 요구사항 초안

ANALYSIS 참고용으로 보고자가 정리한 PoC 요구사항 초안의 요점이다. 확정된 방안이 아니며, 담당자와 함께 조정한다. 아래 수치는 모두 2026-11-06에 공개 REST API를 로그인 없이 조회해 얻었다.

### 현재 검색의 기준선

Duplicate로 닫힌 이슈 249건에서 연결된 이슈의 쌍 312개를 모았다. 그중 연결된 이슈가 먼저 생성된 202쌍에 대해, 중복 이슈의 제목 단어를 그대로 `text ~`에 넣어 검색했다.

| 검색 방식 | 연결된 이슈가 상위 10위 안에 드는 비율 |
|---|---|
| 제목 단어를 그대로 넣은 검색(AND) | 8.9% (18/202). 쿼리의 85%가 0건을 돌려준다 |
| 같은 단어를 OR로 묶은 검색 | 51.0% (103/202) |
| 2026년에 생성된 중복, AND 검색 | 0% (0/70) |
| 두 제목 중 한쪽에만 한글이 있는 쌍, OR 검색 | 15.6% (5/32) |

JIRA 검색은 여러 단어를 AND로 묶고, 모든 단어가 한 필드 안에 있어야 맞으며, 한국어 조사를 분리하지 않는다. 2026년 중복 쌍의 31.4%는 두 제목 중 한쪽에만 한글이 있다.

### 제안하는 요구사항

- 등록 전 검사와 사후 검사를 모두 둔다. 사후 검사는 웹 화면이나 다른 경로로 등록된 새 이슈를 정한 구간마다 검사한다.
- 판정은 `duplicate`, `related`, `unrelated` 세 가지다. 부모와 하위 작업, 수정된 빌드에서 생긴 회귀는 같은 결함의 중복 신고라는 근거가 없으면 `related`로 본다.
- 검사기는 JIRA에 쓰지 않는다. 종료 코드는 0(중복 없음), 1(중복 있음), 2(오류 또는 불완전)이고, 에이전트는 1과 2에서 등록을 보류한다.
- 비교 대상은 검사 시점까지 생성된 모든 공개 CBRD 이슈다. 연결된 이슈가 먼저 생성된 202쌍 중 39.6%는 1일 안에 중복이 등록되어서, 하루 한 번 갱신으로는 부족하다.
- 합격 기준은 연결된 이슈의 recall@10 0.8 이상과 `duplicate` 판정 정밀도 0.8 이상이다. recall@10은 2026년에 생성된 중복만 따로 세어도 0.8 이상이어야 한다. 정밀도의 정답은 사람이 검수한 관계 라벨로 정한다. 연결 경로(링크, 댓글)만으로는 중복인지 관련인지 구분되지 않기 때문이다.
- 평가는 질의 이슈가 등록된 시점의 정보만 쓴다. 제목과 설명은 변경 이력으로 그 시점의 내용으로 되돌리고, 그 뒤에 달린 댓글과 링크, resolution은 쓰지 않는다.

### 담당자와 정할 것

- 관계 라벨을 누가 검수할지. 대상은 Duplicate 링크 쌍 74개와 댓글에 중복 단서가 있는 쌍 44개부터다.
- `duplicate` 판정 검출률에 하한을 둘지.
